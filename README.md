# 排球战术台（volleyball-site）

排球 5-1 站位 / 二传插上 / 反轮可视化 + 球队身体条件分析 + 世界强队数据对比 + 比赛计分器。
纯静态、零依赖、零成本，全部逻辑在浏览器里跑。

## 本地预览（必须用服务器打开）

直接双击 `index.html` 时，浏览器会拦截 `fetch('players.json')`，世界数据加载不出来。
在 `volleyball-site` 目录下执行：

```bash
node serve.js
```

然后浏览器打开 <http://localhost:5173> 。按 `Ctrl+C` 停止。

如果提示 `EADDRINUSE: address already in use ::5173`，说明 5173 被别的程序占了（常见是之前开过的窗口没关）。有两种处理：

1. 直接打开 <http://localhost:5173> 看看——可能之前那个服务还在跑，能用；
2. 换个端口：`node serve.js 8080`，或 `$env:PORT=8080; node serve.js`（新版 serve.js 在端口被占时会自动往后试 5174、5175…，并打印实际地址）。

## 怎么用（轮次 / 站位表现）

工具页第一块是六轮站位演示，交互如下：

- **场地读法**：球网在上方，网前是前排（2、3、4 号位），中间那条**虚线就是三米线（进攻线）**，线后面是后排（1、5、6 号位）。后排球员必须在三米线后起跳进攻，前排不受这条线限制。
- **◀ ▶ / 键盘 ← →**：切轮次（第 1–6 轮），轮次徽章和下面的说明会一起更新。
- **二传在 [号位]**：选二传在第 1 轮的起始号位（默认 6 号位），其余 5 人按录入顺序顺时针排下去。
- **「变化：接发球站位」**：默认是发球前的标准站位；点一下，六个人会带动画换成接发球时的实际阵型——**三个一传手拉成半圆，左后 / 中后 / 右后各守一片**，二传（在后排时）插到 2-3 号位之间，前排不接一传的人留在网口。再点一下回到标准站位。
  - 谁接一传的优先级：自由人 → 后排副攻（队里没有自由人时）→ 主攻 → 接应（还缺人时），最多 3 人。
  - 片区冲突时会自动换位：中后场一定交给后排的人（避免后排没人、或者两个人挤在同一个角）。
  - 说明栏会直接写出「本轮一传：X（左后，主攻）· Y（中后，后排副攻）…」，球员身上也有「一传」徽章，不会有“没人接一传”的情况。
  - 没有自由人时提示“中后场由后排副攻顶着，真实比赛该换自由人”；自由人被放到前排号位会报错提示。
- **插上路线**：二传在后排时画一条橙色弧线（只从外侧绕，不横穿队友）指向 2-3 号位之间；在前排时画蓝色虚线（只是调整传球位置，不需要插上）。
- **反轮提示**：接应轮到 4 号位那一轮，说明里会标「反轮」，并给出两种处理思路。
- **自由人提示**：后排的副攻位置会被自由人替下，说明里会指出是哪个号位。
- **拖动 / 双击**：球员可拖动（松手回标准站位，纯视觉演示）；双击打开对话框改名字和位置。
- **分享链接带状态**：`?round=3&shift=1&setter=1` 可以指定轮次、接发球视角、二传起始号位，发给队友直接看那一轮。

## 球队录入：体重、BMI 与打法分析

每个球员卡片可以填：位置 / 身高 / **体重** / 扣球高度 / 拦网高度 / 惯用手。

- **BMI 与体重档位**：填了身高和体重就自动算 BMI，分四档——轻（<18.5）、均衡（18.5–24）、微胖（24–28）、胖（≥28）。卡片右上角实时显示 `BMI x.x · 档位`。
- **跑位跟着体重变**：每档给一个“机动性”（轻 100%、均衡 85%、微胖 62%、胖 42%）。点“变化：接发球站位”后，六个人的位置按机动性算——体重档位越低，接发球站位越往场内收，二传插上点也越靠中间（100% 时约 63% 宽度，42% 时收到约 53%）。改体重的输入框，球场上的位置会立刻跟着动。
- **队伍特征**：一传 / 二传 / 攻手三项自评（偏弱 / 一般 / 强），只影响打法与战术推荐，不影响身高体重计算。
- **战术匹配**：内置 12 个战术（定点强攻、调整攻、打手出界、吊球、平拉开、后排进攻、前快、背飞、交叉、梯次、双快、二次球），每个战术标了需要的一传/二传/攻手档位。都够 → **可以打**；只差一项 → **可以练**；差两项以上 → **暂别打**。报告里还会指出“最该先补的一项”和对应训练建议。
- **报告里的数据口径**：平均身高不含自由人；平均扣球/拦网只算主攻 + 接应 + 副攻（二传的扣球高度不参与，避免把平均拉低）；留空按身高估算的值会标“（估）”。

## 比赛计分（独立页面 scoreboard.html）

计分单独做成了一个页面，工具页只留下入口按钮，两边数据通过浏览器本地存储共享（`localStorage` 的 `vb_match_v1`），刷新不丢。

- 三栏布局：**我方在左、局分信息在中间、对手在右**，手机上也是左右排（只把字号缩小）。
- 两支队名可以直接改（默认“我方 / 对手”），发球方会高亮。
- 点 **得分 +1**：按每球得分制记分。**接发球方赢球 → 换发球**；勾选“我方接发球得分时自动轮转站位”后，我方拿回发球权会自动把轮次推进一位（和 5-1 的轮转规则一致），轮次号显示在下面的轮次条里。
- **局末自动判定**：25 分且领先 2 分算赢一局；五局三胜的第 5 局、三局两胜的第 3 局自动改成 15 分制；24:24 会一直打到领先 2 分。
- 会提示 **局点 / 赛点**；每局结束把比分写进历史记录（如“第1局 25:22 我方 胜”），比分清零、进入下一局。
- **撤销上一分** 可以还原比分、局分、发球方和已结束的局；**重置本局 / 重置全场** 分别清当前局和整场。
- 赛制下拉：五局三胜 / 三局两胜（切换会重新开一场）；键盘也能记分：A / 1 我方加分，B / 2 对手加分，U 撤销。

## 页面结构

工具页按 ① 轮次站位 → ② 球队录入 → ③ 分析报告 → ④ 世界数据 → ⑤ 教程 五个模块排，比赛计分是独立的 `scoreboard.html`（导航第二项）。
长说明收进「这个图怎么读？」折叠块，避免一屏全是文字。
分析报告顶部有 4 个关键结论块（推荐阵型 / 最强进攻点 / 最先要补 / 现在能打几套战术），小标题左侧有橙色标记，重要结论用高亮块，一眼能看到重点。
世界数据做成紧凑单行：默认只显示前 8 支队伍，点「展开全部」看完整 51 支，每行点“看球员”展开个人数据。

## 部署（二选一，都免费）

### 方案 A：Cloudflare Pages（推荐）
1. 注册 Cloudflare → Workers & Pages → Create → Pages → Upload assets。
2. 把整个 `volleyball-site` 目录拖进去，Deploy。
3. 会得到一个 `xxx.pages.dev` 的免费域名，国内能访问但不稳定。
4. 之后要绑自己的域名，在 Pages → Custom domains 里加，DNS 托管在 Cloudflare 即可。

### 方案 B：GitHub Pages
1. 新建仓库，把 `volleyball-site` 内容推到 `main`。
2. Settings → Pages → Source 选 `main` / root，保存。
3. 得到 `https://用户名.github.io/仓库名/` 。注意：如果仓库不是 `<用户名>.github.io`，资源要用相对路径——本项目全部是相对路径，可直接用。

## 怎么改球员数据

编辑 `players.json` 的 `players` 数组，每条：

```json
{ "id": "w-cn-z2", "name": "朱婷", "team": "中国女排", "country": "CHN",
  "gender": "W", "pos": "主攻", "height": 198, "spike": 327, "block": 315, "hand": "右" }
```

- `gender`: `W` 女排 / `M` 男排
- `pos`: 二传 / 主攻 / 副攻 / 接应 / 自由人
- `spike` 或 `block` 写 `null` 表示公开资料缺失，页面会按身高估算并标注“估”；`height` 写 `null` 则该球员不参与平均身高统计
- `team` 是分组统计用的，加新球队直接新起一个 team 名即可（同一国家可以拆成两支不同 team 名，页面按 team 分组）

当前库内 171 名球员（女排 / 男排），覆盖 40+ 支队伍；页面按“女排 / 男排”两个按钮切换查看，每支队可展开球员明细。

**平均值规则**：一支队伍满 5 人才显示“平均身高 / 平均扣球 / 平均拦网”；不足 5 人的（很多国家只收录了 1-3 名代表球员）不计算平均值，卡片上直接列个人数据，排序也排在有平均值的队伍之后。“与顶尖水平的差距”表同样只列满 5 人的队伍。阈值写在 `app.js` 的 `MIN_SAMPLE = 5`。

## 球员头像

不使用真实照片：每位球员显示“姓名首字 + 位置配色”的圆形徽章，纯本地渲染，无外链、无版权风险，也不会裂图。
`app.js` 的 `avatar()` 仍保留了 `photo` 字段支持，将来真要用本地图片，放 `assets/players/<id>.jpg` 并在球员上补 `"photo": "assets/players/<id>.jpg"` 即可。

## 数据来源与免责

身高、扣球高度、拦网高度来自 FIVB、各国排协和公开媒体报道，不同年份会有出入，仅用于对比参考。
页面上的“估算值”由经验公式得出：扣球高度 ≈ 身高 + 47 cm，拦网高度 ≈ 扣球高度 − 40 cm。
